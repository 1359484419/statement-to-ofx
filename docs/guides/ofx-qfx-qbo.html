OFX vs QFX vs QBO: what is inside each file, and why imports fail

All three are the same thing underneath: an Open Financial Exchange (OFX) bank statement. The differences are in the header, one extra element, and what the importing program is willing to accept.

The short version

FileWhat it isTypical use
.ofx (1.0.2)SGML text with a plain OFXHEADER:100 header. Leaf elements are not closed.Most banks (including Brazilian banks), GnuCash, Moneydance, many accounting systems.
.ofx (2.x)Well-formed XML with an <?OFX OFXHEADER="200" ...?> processing instruction.Newer apps; anything that prefers XML.
.qfxOFX 1.0.2 plus an <INTU.BID> element identifying the bank.Web Connect import for use with Quicken.
.qboSame structure as QFX, with the .qbo extension.Web Connect import into QuickBooks Desktop.

What a minimal statement looks like

<OFX>
 <SIGNONMSGSRSV1><SONRS> ... <INTU.BID>3000 </SONRS></SIGNONMSGSRSV1>
 <BANKMSGSRSV1><STMTTRNRS><STMTRS>
  <CURDEF>USD
  <BANKACCTFROM><BANKID>123456789<ACCTID>4321<ACCTTYPE>CHECKING</BANKACCTFROM>
  <BANKTRANLIST>
   <STMTTRN><TRNTYPE>DEBIT<DTPOSTED>20260105<TRNAMT>-42.10
            <FITID>9f2c...<NAME>GROCERY OUTLET</STMTTRN>
  </BANKTRANLIST>
  <LEDGERBAL><BALAMT>1250.00<DTASOF>20260131</LEDGERBAL>
 </STMTRS></STMTTRNRS></BANKMSGSRSV1>
</OFX>

Credit cards use CREDITCARDMSGSRSV1 / CCSTMTRS / CCACCTFROM instead of the bank aggregates, and have no bank ID.

Six reasons an import goes wrong

1. Every amount has the wrong sign

TRNAMT is from the account holder's point of view: money leaving the account is negative. Card statements usually print purchases as positive numbers, so a straight copy turns every purchase into a payment. In the converter, tick “Flip all signs” for those statements and check the balance line again.

2. Transactions are duplicated, or silently skipped

Importers de-duplicate by FITID. If a converter makes random IDs, importing the same month twice doubles it. If it uses only date and amount, two identical coffees on one day collapse into one. Statement Bridge hashes date, amount, description and the occurrence number of identical rows, so the IDs are stable across re-exports and still unique within a file.

3. “This financial institution is not supported”

Quicken and QuickBooks Desktop read INTU.BID to decide which bank the Web Connect file belongs to, and may refuse IDs they do not recognise or that are not enabled for Web Connect. The value is a number assigned to each institution. If your import is refused, try your own bank's ID (it appears in any QFX/QBO file your bank has given you), or import a plain OFX file where your program offers that. We mark QFX and QBO as experimental for this reason.

4. Dates land in the wrong month

OFX dates are YYYYMMDD, so the problem is always on the input side: 03/04/2026 is 4 March in the US and 3 April almost everywhere else. The column wizard guesses from values above 12, and lets you switch the order. PDF statements often print dates without a year; the converter takes the year from the statement period and rolls over at December to January.

5. Accented names turn into junk

OFX 1.0.2 declares its character set in the header (CHARSET:1252 here), and the bytes must match. Writing UTF-8 bytes under a 1252 header is a common cause of “SÃ£O PAULO”. This converter encodes OFX 1.0.2, QFX and QBO in Windows-1252, and writes OFX 2.x as plain ASCII with XML character references, which the OFX readers we test against (ofxparse and ofxtools) load without errors.

6. The ending balance does not match

LEDGERBAL should be the statement's closing balance. If rows are missing or a sign is wrong, the imported balance drifts. That is why the converter checks opening balance + transactions = closing balance before it lets you export.

Which one should I pick?

  • Your program imports “OFX” or “Money/OFX” files: use OFX 1.0.2 first, OFX 2.2 if that is refused.
  • Quicken: QFX. If it is refused, check the INTU.BID value.
  • QuickBooks Desktop bank feeds: QBO.
  • Xero: either OFX or the Xero CSV layout.
