What it handles today

  • CSV, TSV and TXT exports from any bank. The column wizard detects the header row, the delimiter (comma, semicolon, tab), date order and decimal separator, including formats like 1.234,56 and 11'373.94. It understands a single signed amount column, separate debit/credit columns, or an amount plus a D/C flag column.
  • Excel and LibreOffice files (XLSX, XLS, ODS), with real date and number cells.
  • Text-based PDF statements. The PDF reader finds rows that start with a date and end with amounts, reads column headers such as Withdrawals / Deposits / Balance, joins descriptions that wrap onto a second line, and picks up the opening and closing balance. It is a general heuristic, not a set of per-bank templates, so always look at the review table before exporting. Scanned PDFs (pictures of paper) have no text and are not supported yet.

Checks before you export

Most import problems come from a wrong sign or a missed row. Before the download buttons unlock, the review step checks:

  • that every running balance equals the previous balance plus the transaction (statements in newest-first order are handled);
  • that opening balance + all transactions = closing balance, using the balances printed on the statement when they are there;
  • bad or missing dates, zero amounts, and rows that look like duplicates.

Rows that fail are highlighted, and you can edit any date, description, amount or balance in place.

Output formats

  • OFX 2.2 (XML) and OFX 1.0.2 (SGML) for apps that import Open Financial Exchange files, such as GnuCash, Moneydance and many budgeting tools.
  • QFX, a Web Connect file for use with Quicken, and QBO, a Web Connect file for QuickBooks Desktop. Both are marked experimental: these programs check the financial institution ID (INTU.BID) inside the file, and we cannot test every version. How the formats differ.
  • Xero CSV in the bank statement import layout. Tips for importing it.

Each transaction gets a stable ID (FITID) built from its date, amount and description, so exporting the same statement twice does not create duplicates when your app de-duplicates by ID.

Questions

Is my statement uploaded anywhere?
No. The page reads the file with your browser's File API and builds the output in memory. The site sends a Content-Security-Policy that only allows network requests back to this site, and there is no analytics or tracking script. How to verify this yourself.
Which banks are supported?
Any bank whose export has dates and amounts in columns. A few layouts are recognized automatically (for example the CSV layouts used by Capital One cards, Schwab checking, Payoneer, N26 and UBS, as seen in public sample files). We do not claim support for any specific bank's PDF layout; the PDF reader is generic, and the balance checks are there to catch what it gets wrong.
My card statement shows purchases as positive numbers.
Tick “Flip all signs”. OFX files expect purchases on a credit card to be negative.
Quicken or QuickBooks says the bank is not supported.
Those programs only accept Web Connect files that name a financial institution ID they know. Change the INTU.BID field to your bank's ID, or import the plain OFX file where your program allows it.
Does it work offline?
Once the page has loaded, conversion needs no connection. You can also run it from a local copy; see the project README.
